# Customers 360 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an interactive, read-only Customer Intelligence page inside the dashboard using real paid POS and wash history data.

**Architecture:** Add a focused backend service on `mrp.production` for customer summary/detail data, extend dashboard state/navigation for Customers, and render the page in the existing OWL/QWeb shell. Reuse the established drill-down/open-record patterns and localization helper.

**Tech Stack:** Odoo 18 Enterprise, ORM, POS, MRP, OWL/QWeb, JavaScript, CSS, unittest static contracts.

**Spec:** `docs/superpowers/specs/2026-09-19-customers-360-design.md`

## Global Constraints
- Revenue/visit truth comes from paid POS orders only.
- Company scoped.
- Read-only: no create/write/unlink from Customers 360.
- Live Car Journey remains separate and unchanged.
- New labels must be English/Arabic localized from day one.

## Review Focus
- Walk-in POS orders without a partner do not become fake customers.
- Customers with multiple order lines count one visit per POS order, not per line.
- Search by phone/plate handles missing values safely.
- Customers with POS history but no linked MRP wash still render correctly.
- Segments are deterministic and do not mutate partner categories.
